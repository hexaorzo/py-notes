File Handling in Python

Topics: Persistence · open() · Modes · Paths · write() · read() · readline() · readlines() · strip() · with · CSV

Why File Handling?

  • Variables, lists, dicts are lost when program ends
  • Files store data permanently on secondary storage
  • Allows reading and writing large records
  • Separates program logic from stored data

File Types in Python

  • Text files — line-based readable data (.txt)
  • CSV files — tabular row-column data (.csv)
  • Others — .py, .pdf, .png (not covered here)
  • Beginner focus: text files → CSV files

Basic Workflow

  • Open the file with open()
  • Perform read or write operations
  • Close the file with close()
  • Or use with open(...) — preferred style

Key Ideas

  • File object ≠ actual file (it is the connection)
  • All data read from file is string by default
  • Numeric data must be converted before use
  • strip() removes trailing \n from lines

File Modes at a Glance

Mode Purpose File Must Exist? Old Content Preserved? Where Writing Starts
"r" Read only Yes Yes —
"w" Write (overwrite) No No Beginning
"a" Append No Yes End

01 Why File Handling is Needed
The Problem
  • All variables, lists, dictionaries live in memory
  • Memory is wiped when the program terminates
  • Output disappears; computed results are lost
  • Data must be re-entered every run
Key Insight: File handling separates program logic from stored data — the same program becomes reusable for different input files.
Without vs With Files
# WITHOUT — hardcoded, disposable
marks = [78, 85, 91, 67]
total = sum(marks)
print(total)   # output vanishes after run

# WITH — persistent
# marks stored in marks.txt
# Python reads, processes, saves results
# results available for future use
02 What is a File?
Definition

A file is a named storage unit kept on secondary storage (hard disk, SSD, USB).

  • Text file — stores readable characters line by line
  • CSV file — stores tabular data separated by commas
Observation: Text files are useful for simple line-based data. CSV files are useful when data has rows and columns.
Examples
# Text file — students.txt
Aman
Ravi
Neha

# CSV file — marks.csv
name,marks,grade
Aman,87,A
Ravi,76,B
Neha,91,A
03 File Handling Workflow
Steps
  • Step 1 — Open the file using open()
  • Step 2 — Perform read or write operations
  • Step 3 — Close the file using close()
⚑ Note: The file object f is not the file itself. It is the program-side connection through which Python communicates with the file on disk.
General Structure
f = open("data.txt", "r")
# perform read or write here
f.close()

# open() — creates the connection
# "data.txt" — file name
# "r" — mode (read)
# f — the file object
# close() — ends the connection
04 File Modes — r, w, a
Modes Explained
  • "r" — reads an existing file; file must exist
  • "w" — writes and overwrites existing content; creates file if absent
  • "a" — appends at the end without deleting old content
✗ Caution: "w" mode erases old content silently — dangerous if used carelessly.
✓ Rule: Decide before opening — are you reading, replacing, or adding?
Examples
f1 = open("data.txt", "r")  # read
f2 = open("data.txt", "w")  # write
f3 = open("data.txt", "a")  # append

# "r" — file must already exist
# "w" — creates if missing, wipes if present
# "a" — creates if missing, preserves if present
05 File Path
Path Types
  • Default — Python searches the current working directory
  • Relative path — relative to current folder
  • Absolute path — full path from root of drive
⚑ Windows Caution: Use forward slashes / or a raw string r"..." to avoid backslash issues.
Observation: Many file errors occur not because the file is missing, but because Python is looking in the wrong folder.
Examples
# Default (same folder as script)
open("data.txt", "r")

# Relative path
open("files/data.txt", "r")

# Absolute path — Windows (safe forms)
open("C:/Users/Rajesh/Desktop/data.txt", "r")
open(r"C:\Users\Rajesh\Desktop\data.txt", "r")
06 Writing with write()
Concept
  • write() writes a single string into a file
  • Accepts only string data — not int, float, etc.
  • Numeric values must be wrapped in str()
✗ Mistake: f.write(100) → TypeError: write() argument must be str, not int
✓ Fix: f.write(str(100))
Demo
f = open("message.txt", "w")
f.write("Python file handling is useful.")
f.close()

# File content after execution:
# Python file handling is useful.

# Writing a number correctly:
f = open("data.txt", "w")
f.write(str(100))
f.close()
07 Writing Multiple Lines — \n
Key Rule
  • write() does not add a newline automatically
  • The newline character \n must be written explicitly
  • Unlike print(), which adds \n by default
✗ Mistake: Forgetting \n runs all values together: AmanRaviNeha
✓ Fix: Always append \n to each string before writing
With vs Without \n
# Correct — separate lines
f = open("students.txt", "w")
f.write("Aman\n")
f.write("Ravi\n")
f.write("Neha\n")
f.close()
# File: Aman / Ravi / Neha (3 lines)

# Wrong — all on one line
f.write("Aman")
f.write("Ravi")
# File: AmanRavi
08 Writing Multiple Lines with writelines()
Concept
  • writelines() accepts a list (or any iterable) of strings
  • Writes all strings one after another
  • Does not add newlines automatically — just like write()
  • Each string in the list must already contain \n
Observation: writelines() writes strings exactly as supplied — supply the newlines yourself.
Demo
# Correct — \n already in each string
names = ["Aman\n", "Ravi\n", "Neha\n"]
f = open("students.txt", "w")
f.writelines(names)
f.close()
# File: Aman / Ravi / Neha (3 lines)

# Wrong — no \n
names = ["Aman", "Ravi", "Neha"]
f.writelines(names)
# File: AmanRaviNeha
09 Reading Complete File with read()
Concept
  • read() returns the entire file as one string
  • Even multi-line files are one string (with \n inside)
  • Return type is always str
  • Best for small files where all content is needed at once
Observation: read() is useful when the complete content is small enough to process together.
Demo
# message.txt contains:
# Python is powerful.
# File handling is important.

f = open("message.txt", "r")
data = f.read()
f.close()

print(data)
# Python is powerful.
# File handling is important.

print(type(data))   # <class 'str'>
10 Reading One Line at a Time with readline()
Concept
  • readline() reads exactly one line per call
  • Each line read already includes a \n at the end
  • print() adds its own \n → causes blank line between output
  • Use print(line, end="") to suppress the extra newline
Observation: readline() is useful for controlled line-by-line reading.
Demo
f = open("students.txt", "r")
line1 = f.readline()
line2 = f.readline()
line3 = f.readline()
f.close()

# Cleaner output (no double spacing):
print(line1, end="")
print(line2, end="")
print(line3, end="")
# Aman
# Ravi
# Neha
11 Reading All Lines with readlines()
Concept
  • readlines() reads all lines at once into a list
  • Each list element is one line (string, with \n included)
  • Return type is list
  • For very large files, storing all lines at once may be inefficient
Observation: readlines() connects file handling with list processing naturally.
Demo
f = open("students.txt", "r")
lines = f.readlines()
f.close()

print(lines)
# ['Aman\n', 'Ravi\n', 'Neha\n']

print(type(lines))   # <class 'list'>

# Display cleanly:
for line in lines:
    print(line, end="")
# Aman / Ravi / Neha
12 Direct File Traversal (Loop over File Object)
Concept
  • A file object can be iterated directly in a for loop
  • Each iteration yields one line (including \n)
  • Does not load the entire file into memory — efficient for large files
  • Cleanest style for line-by-line processing
Observation: For line-based processing, direct traversal is usually the cleanest and most memory-efficient approach.
Demo
# marks.txt contains: 78, 85, 91, 67

f = open("marks.txt", "r")
for line in f:
    print(line, end="")
f.close()

# Output:
# 78
# 85
# 91
# 67
13 Reading Numbers from a File
Key Rule
  • All data read from a text file is a string
  • Arithmetic cannot be done on strings
  • Must convert using int() or float() before calculation
  • strip() is needed first to remove trailing \n
✗ Mistake: total += line → TypeError (can't add string to int)
✓ Fix: total += int(line.strip())
Demo
f = open("marks.txt", "r")
total = 0
count = 0
for line in f:
    mark = int(line.strip())
    total += mark
    count += 1
f.close()

average = total / count
print("Total =", total)      # 321
print("Average =", average)  # 80.25
14 Importance of strip()
Why strip() Matters
  • Lines read from a file include a trailing \n
  • This causes problems in comparisons, conversions, and storage
  • strip() removes leading and trailing whitespace including \n
  • Essential before int(), float(), == comparisons
Observation: strip() is almost always needed whenever processing values read from a file.
Demo
line = "Aman\n"
print(repr(line))          # 'Aman\n'

clean = line.strip()
print(repr(clean))         # 'Aman'

# In file reading:
f = open("students.txt", "r")
for line in f:
    name = line.strip()
    print("Name =", name)
f.close()
# Name = Aman
# Name = Ravi
# Name = Neha
15 Appending Data with Mode "a"
Concept
  • Mode "a" opens a file for writing at the end
  • Existing content is preserved — nothing is erased
  • If the file does not exist, it is created fresh
  • Ideal for log files, attendance, transaction records
⚑ Note: If "w" is used instead of "a" when adding entries, all previous records will be permanently lost.
Demo
# First run — create file
f = open("log.txt", "w")
f.write("Program started\n")
f.close()

# Second run — append more
f = open("log.txt", "a")
f.write("Data processed\n")
f.write("Program completed\n")
f.close()

# Final file content:
# Program started
# Data processed
# Program completed
16 Recommended Style — with open(...)
Why Prefer with open()?
  • File is closed automatically when the block ends
  • Works correctly even if an error occurs inside the block
  • No need to manually call close()
  • Cleaner, safer, and widely used in real Python programs
Observation: Manual open() and close() help in understanding the workflow. But with open(...) should be preferred in actual programs.
Demo
# Writing
with open("message.txt", "w") as f:
    f.write("Learning file handling.")
# file automatically closed here

# Reading
with open("message.txt", "r") as f:
    data = f.read()

print(data)
# Learning file handling.
17 Encoding — Brief Introduction
Concept
  • Text files store characters using an encoding system
  • For normal English text, default encoding usually works
  • For special characters or multilingual text, specify encoding explicitly
  • encoding="utf-8" is the recommended standard
Good Habit: Writing encoding="utf-8" even for simple files is a safe, professional practice.
Demo
# Writing with encoding
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("Python supports Unicode text.")

# Reading with same encoding
with open("notes.txt", "r", encoding="utf-8") as f:
    data = f.read()

print(data)
# Python supports Unicode text.
18 Example — Count Lines, Words, Characters
Problem

Read a text file and count: number of lines, words, and characters.

Assume story.txt contains:

  • Python is simple.
  • File handling is useful.
Observation: This example combines file handling, strings, loops, and counting logic into one clean program.
Code & Output
line_count = 0
word_count = 0
char_count = 0

with open("story.txt", "r", encoding="utf-8") as f:
    for line in f:
        line_count += 1
        word_count += len(line.split())
        char_count += len(line)

print("Lines =", line_count)     # 2
print("Words =", word_count)     # 7
print("Characters =", char_count) # 43
19 Example — Filter Records from a File
Problem

File marks.txt has comma-separated student records. Print only students who scored ≥ 80.

File contents:

  • Aman,87
  • Ravi,76
  • Neha,91
  • Karan,68
Observation: Plain text files can store structured data, but manual splitting becomes necessary — this naturally leads to CSV handling.
Code & Output
with open("marks.txt", "r", encoding="utf-8") as f:
    for line in f:
        parts = line.strip().split(",")
        name  = parts[0]
        marks = int(parts[1])
        if marks >= 80:
            print(name, marks)

# Output:
# Aman 87
# Neha 91

# Uses: traversal · strip() · split()
#       list indexing · int() · condition
20 Common File Handling Errors
Error 1 — File Not Found
open("unknown.txt", "r")
# FileNotFoundError
✓ Fix: Verify the file name and path before opening in "r" mode.
Error 2 — Accidental Overwrite
open("records.txt", "w")
# All old content erased!
✗ Caution: "w" does not ask for confirmation — it silently overwrites.
Error 3 — Writing Non-String
f.write(100)
# TypeError: must be str, not int
✓ Fix: Always use str(100) when writing numeric data.
Error 4 — Missing \n / Type Conversion
f.write("Aman")
f.write("Ravi")  # → AmanRavi

total += line   # → TypeError
✓ Fix: Add \n when writing; use int(line.strip()) before arithmetic.
