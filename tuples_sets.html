Tuples & Sets in Python

Topics: Immutability · Packing & Unpacking · Set Algebra · Hashability · Frozenset · Comprehensions

Tuple at a Glance

  • Ordered — preserves insertion sequence
  • Immutable — elements cannot be changed
  • Allows duplicates
  • Supports indexing, slicing, loops
  • Can store mixed data types

Set at a Glance

  • Unordered — no fixed positions
  • Mutable — elements can be added/removed
  • No duplicates — unique values only
  • No indexing or slicing
  • Elements must be hashable

When to Use Tuple

  • Data that should not change (coords, dates)
  • Returning multiple values from a function
  • Dictionary keys (compound key)
  • Grouping fixed records: (name, roll, dept)

When to Use Set

  • Remove duplicates from a collection
  • Fast membership checking
  • Union, intersection, difference of groups
  • Distinct value counting

Tuples
01 Creating Tuples — Basic Syntax
Concept
  • Standard form uses () with comma-separated values.
  • Can hold integers, strings, floats, booleans, mixed types, even other tuples or lists.
  • Homogeneous — all same type.
  • Heterogeneous — mixed types.
Demo
t1 = (10, 20, 30)
t2 = ("red", "green", "blue")
t3 = (10, "python", 3.5, True)
print(t1)   # (10, 20, 30)
print(t2)   # ('red', 'green', 'blue')
print(t3)   # (10, 'python', 3.5, True)
02 Empty Tuple & Singleton Tuple
Critical Syntax Rule
  • () → empty tuple
  • (5,) → one-element tuple (trailing comma required)
  • (5) → just an integer in parentheses — NOT a tuple!
✗ Mistake: b = (5) — looks like a tuple but is an int.
✓ Fix: b = (5,) — trailing comma makes it a tuple.
Demo
a = ()
b = (5,)
c = (5)
print(type(a))  # <class 'tuple'>
print(type(b))  # <class 'tuple'>
print(type(c))  # <class 'int'>
03 Tuple Packing
Concept
  • Comma is the essential ingredient of a tuple — not parentheses.
  • Python auto-creates a tuple when values are separated by commas, even without ().
  • Parentheses improve readability and are strongly recommended.
Demo
t = 10, 20, 30
print(t)         # (10, 20, 30)
print(type(t))   # <class 'tuple'>
04 Indexing & Negative Indexing
Concept
  • Indexing starts at 0 — same as list and string.
  • Negative index: -1 → last, -2 → second last, etc.
  • Useful when the end of the tuple is more relevant.
Demo
colors = ("red", "green", "blue", "yellow")
print(colors[0])   # red
print(colors[3])   # yellow

vals = (100, 200, 300, 400)
print(vals[-1])   # 400
print(vals[-2])   # 300
05 Length & IndexError
Concept
  • len(t) returns total number of elements.
  • Valid positive indices: 0 to len(t) - 1.
  • Accessing beyond the valid range raises IndexError.
⚠ Caution: Even though tuple is immutable, index errors still occur on out-of-range access.
Demo
seq = (2, "a", 4, (1, 2))
print(len(seq))   # 4  → valid indices: 0,1,2,3

empty_t = ()
print(len(empty_t))   # 0

# print(seq[4])  → IndexError!
06 Slicing
Concept
  • Syntax: t[start:stop] — start included, stop excluded.
  • Omitting start defaults to 0; omitting stop defaults to end.
  • Slicing produces a new tuple — original is unchanged.
Demo
t = (10, 20, 30, 40, 50, 60)
print(t[1:4])  # (20, 30, 40)
print(t[:3])   # (10, 20, 30)
print(t[3:])   # (40, 50, 60)
print(t[:])    # (10, 20, 30, 40, 50, 60)
07 Slicing with Step
Concept
  • Syntax: t[start:stop:step]
  • t[::2] → every other element (even-index)
  • t[1::2] → odd-index elements
  • t[::-1] → reversed copy of the tuple
Demo
t = (10, 20, 30, 40, 50, 60, 70, 80)
print(t[::2])    # (10, 30, 50, 70)
print(t[1::2])   # (20, 40, 60, 80)
print(t[::-1])   # (80, 70, 60, 50, 40, 30, 20, 10)
08 Nested Tuples
Concept
  • A tuple element can itself be another tuple.
  • Nested indexing: first pick outer element, then index into inner tuple.
  • Slicing works on the outer tuple; the inner tuple is treated as a single element.
Demo
seq = (2, "a", 4, (1, 2))
print(seq[3])       # (1, 2)
print(seq[3][0])    # 1
print(seq[1:4:2])   # ('a', (1, 2))
09 Traversal
Concept
  • A tuple is iterable, so for item in t works naturally.
  • Each element is visited in order.
  • Traversal is for reading/processing — the tuple itself cannot be modified.
Demo
t = (2, "a", 4, (1, 2))
for item in t:
    print(item)
# 2
# a
# 4
# (1, 2)
10 Membership Testing
Concept
  • x in t → True if x is an element.
  • x not in t → True if x is absent.
  • Works exactly like string and list membership testing.
Demo
t = (10, 20, 30, 40)
print(20 in t)       # True
print(25 in t)       # False
print(50 not in t)   # True
11 Concatenation & Repetition
Concept
  • + concatenates two tuples into a new tuple.
  • * repeats a tuple n times into a new tuple.
  • Neither operation modifies the original tuple — new objects are created.
Demo
a = (1, 2, 3)
b = (4, 5)
print(a + b)   # (1, 2, 3, 4, 5)
print(a * 3)   # (1, 2, 3, 1, 2, 3, 1, 2, 3)
12 Built-in Functions on Tuples
Concept
  • len(t) — number of elements
  • max(t) — largest element
  • min(t) — smallest element
  • sum(t) — total (numeric tuples only)
⚠ Note: max(), min(), sum() require compatible element types.
Demo
nums = (3, 5, 0, 8)
print(len(nums))   # 4
print(max(nums))   # 8
print(min(nums))   # 0
print(sum(nums))   # 16
13 Tuple Methods — count() and index()
Concept
  • Tuple has only two methods (no mutation methods needed).
  • count(x) — number of times x appears.
  • index(x) — position of first occurrence of x.
  • index(x) raises ValueError if x is not found.
Demo
t = (10, 20, 30, 20, 40, 20)
print(t.count(20))   # 3
print(t.index(20))   # 1  (first position)
14 Immutability — Most Important Property
Concept
  • Once created, tuple elements cannot be reassigned.
  • Attempting t[i] = x raises a TypeError.
  • Tuple allows reading and grouping, but not replacement.
✗ Mistake: t[1] = 4 → TypeError: 'tuple' does not support item assignment.
Demo
t = (2, "mit", 3)
print(t[0])   # 2  — reading is fine

# t[1] = 4   → TypeError!
15 Mutation vs Reassignment
Key Distinction
  • A tuple object cannot be mutated (changed in place).
  • But a variable can be reassigned to point to a completely new tuple — this is NOT mutation.
  • The original tuple object is discarded; a new one is created.
📌 Note: Reassigning t changes what object the variable refers to — the old tuple is untouched.
Demo
t = (2, 4, 3)
print(t)   # (2, 4, 3)

t = (2, 5, 3)   # variable now refers to new tuple
print(t)   # (2, 5, 3)
16 Mutable Object Inside a Tuple
Subtle but Critical Point
  • Tuple immutability applies to its own element positions.
  • If a mutable object (like a list) is stored inside the tuple, that inner object can still change.
  • The tuple structure stays the same; the list contents change.
⚠ Warning: Tuple immutability does NOT make nested mutable objects immutable.
Demo
t = (10, [20, 30], 40)
print(t)            # (10, [20, 30], 40)

t[1].append(50)    # list inside changes!
print(t)            # (10, [20, 30, 50], 40)
17 Tuple Packing & Unpacking
Concept
  • Packing — grouping multiple values into one tuple.
  • Unpacking — distributing tuple elements into separate variables.
  • Number of variables must exactly match the number of elements.
✗ Mistake: a, b = (10, 20, 30) → ValueError: too many values.
Demo
t = (10, 20, 30)  # packing

a, b, c = t         # unpacking
print(a)   # 10
print(b)   # 20
print(c)   # 30
18 Swapping Variables via Tuple Unpacking
Concept
  • Python uses tuple packing and unpacking to swap two variables in one line.
  • No temporary variable is needed.
  • One of the most famous practical uses of tuple unpacking.
Demo
x = 1
y = 2

x, y = y, x   # right side packs into tuple, then unpacks

print(x)   # 2
print(y)   # 1
19 Returning Multiple Values from a Function
Concept
  • A function can formally return only one object.
  • Returning a tuple allows multiple results to be grouped into that one object.
  • Caller can unpack directly into separate variables — very clean pattern.
Demo
def quotient_and_remainder(x, y):
    q = x // y
    r = x % y
    return (q, r)

result = quotient_and_remainder(10, 3)
print(result)          # (3, 1)

quot, rem = quotient_and_remainder(5, 2)
print(quot, rem)        # 2 1
20 *args and Tuple
Concept
  • When *args is used in a function definition, Python collects all extra positional arguments into a tuple.
  • Inside the function, args behaves as a tuple.
  • This is a standard and very important tuple application.
Demo
def mean(*args):
    total = 0
    for x in args:
        total += x
    return total / len(args)

print(mean(1, 2, 3, 4, 5, 6))   # 3.5
21 tuple() Constructor
Concept
  • tuple(iterable) converts any iterable into a tuple.
  • Works with lists, strings, ranges, sets, etc.
  • Useful when generated data must be stored in fixed sequence form.
Demo
a = tuple([10, 20, 30])
b = tuple("python")
c = tuple(range(5))

print(a)   # (10, 20, 30)
print(b)   # ('p', 'y', 't', 'h', 'o', 'n')
print(c)   # (0, 1, 2, 3, 4)
22 Tuple ↔ List Conversion
Concept
  • list(t) → converts tuple to a mutable list.
  • tuple(L) → converts list to an immutable tuple.
  • Useful when data is initially fixed but later needs modification.
  • The original tuple is always unchanged after list().
Demo
t = (10, 20, 30)
L = list(t)
L[1] = 99

print(t)   # (10, 20, 30)  — tuple unchanged
print(L)   # [10, 99, 30]  — list modified
23 Tuple as a Dictionary Key
Concept
  • Because tuple is immutable, it can be used as a dictionary key.
  • Only valid when all elements are hashable.
  • A tuple containing a list cannot be a dict key.
  • Excellent for compound (multi-field) keys.
✗ Invalid: {(1, [2,3]): "x"} → TypeError (list is unhashable).
Demo
points = {
    (0, 0): "origin",
    (1, 2): "A",
    (3, 4): "B"
}
print(points[(1, 2)])   # A

24 Creating Sets — Two Ways
Concept
  • Curly braces literal: {val, val, ...}
  • set() constructor: converts any iterable — list, string, tuple, range.
  • Duplicate values are automatically removed.
  • Strings become sets of unique characters.
Demo
A = {10, 20, 30}
B = {"red", "green", "blue"}
C = {1, 2, 3, 2, 1}   # dupes removed

D = set([1, 2, 3, 2, 1])
E = set("hello")
F = set((10, 20, 10, 30))
print(E)   # {'h', 'e', 'l', 'o'}  (order varies)
25 Empty Set & Duplicate Removal
Critical Syntax Rule
  • {} creates an empty dictionary, NOT a set.
  • set() creates an empty set.
  • Duplicate values are silently discarded on creation.
✗ Mistake: a = {} — this is a dict, not a set!
✓ Fix: a = set() for an empty set.
Demo
a = {}
b = set()
print(type(a))   # <class 'dict'>
print(type(b))   # <class 'set'>

nums = {1, 2, 2, 3, 1, 4, 4}
print(nums)         # {1, 2, 3, 4}
print(len(nums))    # 4
26 Unordered — No Indexing
Concept
  • A set is not a sequence — elements have no fixed positions.
  • Indexing (S[0]) and slicing are not supported.
  • Set answers "Is this value present?" not "What is at position 0?"
✗ Mistake: S[0] → TypeError: 'set' object is not subscriptable.
Demo
S = {10, 20, 30}

# print(S[0])  → TypeError!

# Display order may vary each run:
print(S)   # e.g. {10, 20, 30}
27 Membership Testing & Traversal
Concept
  • x in S and x not in S work naturally and are very fast.
  • Set is extremely efficient for membership checking.
  • Traversal with for item in S works, but order is not guaranteed.
⚠ Note: Never write logic that depends on a particular iteration order of a set.
Demo
S = {10, 20, 30, 40}
print(20 in S)       # True
print(25 in S)       # False
print(50 not in S)   # True

colors = {"red", "green", "blue"}
for item in colors:
    print(item)   # order not fixed
28 Hashability Rule — Valid Set Elements
Concept
  • Set elements must be hashable.
  • Beginner shortcut: most immutable values can be set elements.
  • Valid: int, float, str, bool, tuple (all hashable elements), frozenset.
  • Invalid: list, set, dict, tuple containing unhashable elements.
✗ Invalid: {[1,2], [3,4]} → TypeError: unhashable type: 'list'.
Demo
A = {1, 2, 3}
B = {"a", "b", "c"}
C = {(1, 2), (3, 4)}   # tuples are ok
print(A, B, C)

# D = {[1,2], [3,4]}      → TypeError
# E = {{1,2}, {3,4}}      → TypeError
# F = {(1, [2,3])}        → TypeError
29 add() vs update()
Concept
  • add(x) — inserts exactly one complete object into the set.
  • update(iterable) — extracts elements from an iterable and inserts them one by one.
  • Key difference: add((3,4)) inserts the tuple; update((3,4)) inserts 3 and 4 separately.
Demo
A = {1, 2}
B = {1, 2}

A.add((3, 4))     # tuple added as one object
B.update((3, 4)) # 3 and 4 added separately

print(A)   # {1, 2, (3, 4)}
print(B)   # {1, 2, 3, 4}
30 remove() vs discard()
Concept
  • remove(x) — deletes x; raises KeyError if absent.
  • discard(x) — deletes x if present; does nothing if absent.
  • Use remove() when presence is certain; discard() when uncertain.
Demo
S = {10, 20, 30, 40}
S.remove(20)
print(S)   # {10, 30, 40}

S.discard(99)   # 99 not there — no error
print(S)   # {10, 30, 40}

# S.remove(99)  → KeyError!
31 pop() and clear()
Concept
  • pop() — removes and returns an arbitrary element (not the "last").
  • clear() — removes all elements; the same set object becomes empty.
  • Because set is unordered, "last" has no meaning — never assume which element pop() removes.
⚠ Note: Do not describe set pop() as removing the last element — that is only true for list.
Demo
S = {10, 20, 30}
x = S.pop()     # removes arbitrary element
print(x)
print(S)

T = {1, 2, 3}
T.clear()
print(T)   # set()
32 Aliasing vs copy()
Concept
  • B = A — aliasing; both names refer to the same set object.
  • B = A.copy() — creates an independent shallow copy.
  • Sets, like lists, are mutable, so aliasing must be understood carefully.
✗ Alias trap: modifying B after B = A also modifies A.
Demo
A = {1, 2, 3}
B = A          # alias
B.add(4)
print(A)   # {1, 2, 3, 4}  — A changed too!

A = {1, 2, 3}
B = A.copy()   # real copy
B.add(4)
print(A)   # {1, 2, 3}  — A unchanged
print(B)   # {1, 2, 3, 4}
33 Union & Intersection
Concept
  • Union (| or union()): all distinct elements from both sets.
  • Intersection (& or intersection()): only elements common to both.
  • Both return new set objects; original sets are unchanged.
Demo
A = {1, 2, 3, 4}
B = {3, 4, 5, 6}

print(A | B)               # {1,2,3,4,5,6}
print(A.union(B))          # {1,2,3,4,5,6}

print(A & B)               # {3, 4}
print(A.intersection(B))   # {3, 4}
34 Difference & Symmetric Difference
Concept
  • Difference (- or difference()): elements in A but not in B. Directional!
  • Symmetric Difference (^ or symmetric_difference()): elements in exactly one of the two sets (excludes common overlap).
Demo
A = {1, 2, 3, 4}
B = {3, 4, 5, 6}

print(A - B)                      # {1, 2}
print(A.difference(B))             # {1, 2}
print(B - A)                      # {5, 6}  (directional!)

print(A ^ B)                      # {1, 2, 5, 6}
print(A.symmetric_difference(B))  # {1, 2, 5, 6}
35 Subset, Superset & Equality
Concept
  • A == B → same elements (order doesn't matter).
  • A <= B → A is a subset of B (proper or equal).
  • A < B → A is a proper subset (A ⊂ B, A ≠ B).
  • B >= A → B is a superset of A.
  • < and > for sets mean subset/superset — not numeric comparison.
Demo
A = {1, 2}
B = {1, 2, 3, 4}
C = {2, 1}

print(A == C)   # True  (order irrelevant)
print(A <= B)   # True  (subset)
print(A < B)    # True  (proper subset)
print(B >= A)   # True  (superset)
36 Removing Duplicates from a List
Common Practical Pattern
  • Convert list → set (duplicates removed).
  • Convert set → list to get a list of unique values.
  • Original order is not preserved after this round-trip.
⚠ Note: If order matters, use a different approach (e.g., dict.fromkeys). Set is for uniqueness, not order.
Demo
L = [10, 20, 10, 30, 20, 40, 30]
S = set(L)
unique_list = list(S)

print("Original:", L)
print("Set:", S)
print("Unique list:", unique_list)
# order in unique_list may differ!
37 Frozenset — Immutable Set Type
Concept
  • set — mutable; supports add(), remove(), etc.
  • frozenset — immutable; cannot be modified after creation.
  • Because it is immutable and hashable, a frozenset can be an element of another set or a dictionary key.
Demo
A = frozenset([1, 2, 3, 2, 1])
print(A)          # frozenset({1, 2, 3})
print(type(A))    # <class 'frozenset'>

# frozenset as dict key
d = {frozenset({1,2}): "pair"}
print(d)

# frozenset as element of a set
S = {frozenset({1,2}), frozenset({3,4})}
print(S)
38 Set Comprehension
Concept
  • Syntax: {expr for item in iterable}
  • With filter: {expr for item in iterable if condition}
  • Uniqueness is automatic — duplicates generated by the expression are silently dropped.
Demo
S = {x * x for x in range(1, 6)}
print(S)   # {1, 4, 9, 16, 25}

E = {x for x in range(1, 11) if x % 2 == 0}
print(E)   # {2, 4, 6, 8, 10}

# Duplicates dropped automatically:
D = {x % 3 for x in range(10)}
print(D)   # {0, 1, 2}
39 Subtle Equality Behaviour & Operator vs Method
Equality Subtlety
  • Set uniqueness is based on equality, not appearance.
  • 1, 1.0, and True compare equal in Python — a set will not store all three.
S = {1, 1.0, True}
print(S)   # {1}  — only one entry kept
Operator vs Method Forms
  • | ↔ union()
  • & ↔ intersection()
  • - ↔ difference()
  • ^ ↔ symmetric_difference()
  • Operator form is shorter; method form is clearer for beginners.
