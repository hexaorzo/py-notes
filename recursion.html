Recursion

Topics: Base Case · Descent & Unwinding · Value-Producing · Action-Oriented · Strings · Lists · Tuples · Dicts · Common Errors

What is Recursion?

  • A function that calls itself on a smaller instance of the same problem
  • Solves complex problems by divide-and-reduce logic
  • Execution has two phases: descent and unwinding
  • Every valid recursive function must terminate

Three Requirements

  • Base case — a reachable stopping condition
  • Reduction step — each call moves toward the base case
  • Correct linkage — current call properly uses the smaller result

Types of Recursion

  • Value-producing — returns a computed result
  • Action-oriented — produces output (print)
  • Mixed — does both output and return
  • Multiple recursive calls — e.g. Fibonacci

Data it Works On

  • Numerical: reduce via n-1, n//10
  • Strings: reduce via s[1:]
  • Lists: reduce via L[1:]
  • Tuples and nested dictionaries

Recursion vs Iteration — At a Glance

Property Recursion Iteration
Mechanism Function calls itself Loop repeats a block
Termination Base case Loop condition
Stack usage Uses call stack (can overflow) Constant — no extra stack
Best for Self-similar / divide-reduce problems Simple linear repetition
Readability Elegant for natural recursions (factorial, Fibonacci) More direct for counters, totals
Efficiency risk Higher — duplicate calls possible Lower — usually preferred for large input

01 General Recursive Forms
Value-Producing Form
def f(x):
    if base_case:
        return base_value
    return combine(current_part, f(smaller_problem))
  • Solves the smaller subproblem first
  • Uses the returned result
  • Combines it with the current part
  • Returns the final value upward
Action-Oriented Form
def f(x):
    if base_case:
        return
    work_before(x)
    f(smaller_problem)
    work_after(x)
  • Performs an action before recursing
  • Recurses on the smaller problem
  • Performs another action after return
  • Position of print changes output order
02 Value-Producing Recursion
Concept

The recursive call returns a smaller answer, and the current call builds the larger answer from it.

  • Result of recursive call is used in an expression
  • Final answer is assembled during the unwinding phase
Typical Examples
  • Factorial
  • Sum of digits / list sum
  • List maximum
  • Reverse string
  • Counting occurrences
Demo — Factorial
def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)

print(fact(5))  # 120
⚠ Key: fact(n-1) is used directly inside a multiplication expression — that's what makes it value-producing.
03 Action-Oriented Recursion
Concept

The recursive call is placed between actions such as printing. No value is built and returned — the goal is side effects (output).

  • Print before recursion → descending order
  • Print after recursion → ascending order
Difference: Value-producing uses the result in an expression. Action-oriented uses the call as part of execution flow.
Demo
def show(n):
    if n == 0:
        return
    print(n, end=" ")
    show(n - 1)

show(4)
# Output: 4 3 2 1
✗ Error: return print(n) + f(n-1) → TypeError — print() returns None, which cannot be added to an integer.
04 Mixed Recursion — Output + Return
Concept

A function can both print output and return a computed value.

  • Statements before the recursive call execute during descent
  • Statements after the recursive call execute during unwinding
  • The returned value accumulates during unwinding
Demo
def f(n):
    if n == 0:
        print("B", end=" ")
        return 0
    print("A" + str(n), end=" ")
    x = f(n - 1)
    print("C" + str(n), end=" ")
    return x + n

print(f(3))
# Output: A3 A2 A1 B C1 C2 C3 6
05 Descent Phase & Unwinding Phase
Concept
  • Descent phase: calls keep moving toward the base case
  • Unwinding phase: after base case is reached, calls return one by one
  • Code before the recursive call → runs during descent
  • Code after the recursive call → runs during unwinding
Demo — Trace of f(3)
def f(n):
    if n == 0:
        print("Z", end=" ")
        return
    print("A", n, end=" ")
    f(n - 1)
    print("B", n, end=" ")

f(3)
# Output: A 3  A 2  A 1  Z  B 1  B 2  B 3
#          ←── descent ──→     ←── unwinding ──→
06 Statement Position Changes Output
Print BEFORE Recursion → Descending
def h(n):
    if n == 0:
        return
    print(n, end=" ")
    h(n - 1)

h(5)
# Output: 5 4 3 2 1
Print AFTER Recursion → Ascending
def h(n):
    if n == 0:
        return
    h(n - 1)
    print(n, end=" ")

h(5)
# Output: 1 2 3 4 5
Note: Base case and reduction step are identical. Only statement position changes the visible behaviour.
07 Base Case Present but Not Reachable
Concept

A base case that exists but is never reached is just as bad as having no base case.

  • If the reduction step moves away from the base case, it will never stop
  • Python will raise RecursionError when the call stack overflows
✓ Rule: Recursion needs not only a base case — but a reachable base case via the reduction step.
Broken Example
def g(n):
    if n == 0:       # base case exists
        return 0
    return g(n + 1) # but moves AWAY!

print(g(3))
# calls: g(3)→g(4)→g(5)→...
✗ Result: RecursionError: maximum recursion depth exceeded
08 Factorial — Classic Value Recursion
Mathematical Definition
  • n! = n × (n − 1)!
  • 0! = 1 (base case)
Trace of fact(4)
  • fact(4) = 4 × fact(3)
  • fact(3) = 3 × fact(2)
  • fact(2) = 2 × fact(1)
  • fact(1) = 1 × fact(0) = 1
  • → 4 × 3 × 2 × 1 = 24
Safe Implementation
def fact(n):
    if n < 0:
        return None   # handle invalid input
    if n == 0:
        return 1
    return n * fact(n - 1)

print(fact(5))   # 120
print(fact(0))   # 1
print(fact(-3))  # None
09 Recursive Summation (Selective)
Concept

Not every recursive sum is 1+2+…+n. The recurrence relation defines what gets summed.

Expansion of s(7)
  • s(7) = 7 + s(5)
  • s(5) = 5 + s(3)
  • s(3) = 3 + s(1)
  • s(1) = 1
  • → 7 + 5 + 3 + 1 = 16
Code
def s(n):
    if n <= 1:
        return n
    return n + s(n - 2)  # step by 2!

print(s(7))  # 16
⚠ Note: This sums odd numbers only — not all integers 1 to 7. Always trace the recurrence to understand what is actually computed.
10 Digit Recursion
Key Operations
  • n % 10 → last digit
  • n // 10 → remove last digit
  • Print before recursing → reverse digit order
  • Print after recursing → original digit order
Reverse Order
def show1(n):
    if n == 0:
        return
    print(n % 10, end=" ")
    show1(n // 10)

show1(4836)  # 6 3 8 4
Original Order
def show2(n):
    if n == 0:
        return
    show2(n // 10)
    print(n % 10, end=" ")

show2(4836)  # 4 8 3 6
✗ Common Error: Using / instead of // in digit recursion causes a float and the base case n == 0 may never be hit.
11 Digit-Based Counting
Concept

Recursion on numbers can count specific digits selectively using a conditional check at each step.

Trace of count7(77)
  • 77 % 10 == 7 → 1 + count7(7)
  • 7 % 10 == 7 → 1 + count7(0)
  • count7(0) = 0
  • Total: 2
Code
def count7(n):
    if n == 0:
        return 0
    if n % 10 == 7:
        return 1 + count7(n // 10)
    return count7(n // 10)

print(count7(7702757))  # 4
12 String Recursion — Reverse
Key Reduction
  • s[0] → current first character
  • s[1:] → remaining string (the reduction)
  • Base case: s == ""
  • Reverse: append s[0] after the recursive result
Trace of rev("abc")
  • rev("abc") = rev("bc") + "a"
  • rev("bc") = rev("c") + "b"
  • rev("c") = rev("") + "c" = "c"
  • → "c" + "b" + "a" = "cba"
Code
def rev(s):
    if s == "":
        return ""
    return rev(s[1:]) + s[0]

print(rev("python"))  # nohtyp
Pattern: rev(s[1:]) + s[0] — the current character goes to the end after all smaller results unwind.
13 String Filtering & Character Counting
Removing a Character
def remove_a(s):
    if s == "":
        return ""
    if s[0] == 'a':
        return remove_a(s[1:])
    return s[0] + remove_a(s[1:])

print(remove_a("abracadabra"))
# brcdbr
Counting Occurrences
def count_char(s, ch):
    if s == "":
        return 0
    if s[0] == ch:
        return 1 + count_char(s[1:], ch)
    return count_char(s[1:], ch)

print(count_char("abracadabra", "a"))  # 5
print(count_char("mississippi", "s"))   # 4
14 List Recursion — Sum & Maximum
List Sum
def list_s(L):
    if L == []:
        return 0
    return L[0] + list_s(L[1:])

print(list_s([10, 20, 30, 40]))  # 100
  • List reduction via L[1:] — same pattern as strings
  • Base: empty list returns identity value 0
List Maximum
def list_m(L):
    if len(L) == 1:
        return L[0]
    m = list_m(L[1:])
    if L[0] > m:
        return L[0]
    return m

print(list_m([7, 12, 4, 19, 5]))  # 19
Key: The returned subresult m is compared and used meaningfully — classic value-producing pattern.
15 List Membership Search & Selective Counting
Membership Search
def contains(L, x):
    if L == []:
        return False
    if L[0] == x:
        return True
    return contains(L[1:], x)

print(contains([4,9,2,7], 7))  # True
print(contains([4,9,2,7], 8))  # False
Count Even Elements
def count_even(L):
    if L == []:
        return 0
    if L[0] % 2 == 0:
        return 1 + count_even(L[1:])
    return count_even(L[1:])

print(count_even([2,7,4,9,10,11,6]))  # 4
16 Tuple Recursion
Concept

Tuples support the same T[1:] reduction as lists and strings. Recursion is not limited to lists.

  • Base case: empty tuple ()
  • Reduction: T[1:]
  • Current element: T[0]
Sum of Tuple Elements
def tuple_sum(T):
    if T == ():
        return 0
    return T[0] + tuple_sum(T[1:])

print(tuple_sum((10, 20, 30, 40)))  # 100
Takeaway: Recursive sequence processing works identically on strings, lists, and tuples — only the type of the base case changes.
17 Nested Dictionary Recursion
Concept

Flat dictionaries don't need recursion. Recursion becomes meaningful when values are themselves dictionaries (hierarchical / nested data).

  • Check each value: if it's a dict, recurse into it
  • Otherwise, accumulate the numeric value
  • Uses isinstance(value, dict) to branch
Summing All Nested Values
def nested_values(d):
    total = 0
    for value in d.values():
        if isinstance(value, dict):
            total += nested_values(value)
        else:
            total += value
    return total

data = {"a": 10, "b": {"c": 20, "d": 5},
        "e": {"f": {"g": 15}}}

print(nested_values(data))  # 50
18 Fibonacci — Multiple Recursive Calls
Concept

Some recursive functions call themselves more than once per step. This creates a call tree — not a linear call chain.

  • fib(5) calls fib(4) and fib(3)
  • fib(3) is computed multiple times independently
  • This is logically correct but computationally wasteful
⚠ Important: Correctness and efficiency are separate concerns. A recursive function can be mathematically elegant yet practically slow.
Code
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(6))  # 8

Duplicate subproblems in fib(5):

  • fib(5) = fib(4) + fib(3)
  • fib(4) = fib(3) + fib(2)
  • fib(3) appears more than once → repeated work
19 Mixed Output + Return — Full Trace
Code
def f(n):
    if n <= 0:
        print("X", end=" ")
        return 1
    print(n, end=" ")
    x = f(n - 2)
    print(n, end=" ")
    return x + n

print(f(5))
# Output: 5 3 1 X 1 3 5 10
Call Trace
  • f(5) prints 5, calls f(3)
  • f(3) prints 3, calls f(1)
  • f(1) prints 1, calls f(-1)
  • f(-1) prints X, returns 1
Unwinding + Return Values
  • f(1): prints 1, returns 1+1 = 2
  • f(3): prints 3, returns 2+3 = 5
  • f(5): prints 5, returns 5+5 = 10
  • Final print: 10
20 Common Errors in Recursive Design
Missing / Unreachable Base
✗ Error: No base case, or reduction moves away from it → RecursionError
✓ Fix: Verify the reduction step actually reaches the base case on every path.
Mixing print() and return
return print(n) + f(n-1)
✗ Error: TypeError — print() returns None, can't add to int.
✓ Fix: Separate print and return into different statements.
Digit Recursion with /
f(n / 10)  # ✗ float!
f(n // 10) # ✓ int
✗ Error: n / 10 produces a float — base case n == 0 may never match.
✓ Fix: Always use // for integer digit reduction.
Wrong Return Expression
✗ Error: Forgetting to combine: return f(smaller) without including current_part.
✓ Fix: Always think: what does the current call contribute beyond the recursive result?
Reduction Not Shrinking
✗ Error: Sequence not actually reducing — e.g. passing L instead of L[1:].
✓ Fix: Check that each recursive call receives a strictly smaller input.
Efficiency Blindspot
⚠ Note: Short recursive code ≠ efficient code. Fibonacci recomputes fib(3) many times. Correct and efficient are separate properties.
