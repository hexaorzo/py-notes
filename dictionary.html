Python Dictionary

A mutable mapping type that stores key-value pairs — the go-to structure when data is naturally associative rather than positional.

mutable mapping key → value hashable keys insertion order
01
Why Dictionary is Needed
Problem with parallel lists: Storing student grades in separate names[] and grades[] lists forces index-based searching — fragile, hard to maintain, and hard to read.

Problems (Parallel Lists)

  • Data spread across multiple structures
  • Index consistency must always be maintained
  • Code becomes indirect and error-prone
  • Readability becomes weak
  • Updates can break other lists

Dictionary Solves This

  • Meaningful key gives associated info directly
  • No index management required
  • Cleaner, more readable code
  • Easier updates — one place to change
  • Natural modeling of real-world data
02
What is a Dictionary?

Core Properties

  • Collection of key-value pairs
  • Mapping type (not a sequence)
  • Access is by key, not by position
  • Keys are unique; values may repeat
  • Mutable — can be changed after creation
  • Preserves insertion order (Python 3.7+)

Natural Examples

  • student name → grade
  • product code → price
  • city → population
  • word → frequency count
  • username → profile
  • country → capital
03
Creating Dictionaries
CREATION STYLES 
# Brace notation (most common)
d1 = {"name": "Aman", "age": 20}

# Integer keys
d2 = {1: "one", 2: "two", 3: "three"}

# From list of pairs
d3 = dict([("a", 1), ("b", 2)])

# Keyword arguments
d4 = dict(name="Aman", age=20, city="Jaipur")

# Empty dictionary
d5 = {}

# fromkeys — all keys with same initial value
d6 = dict.fromkeys(["a", "b", "c"], 0)
# → {'a': 0, 'b': 0, 'c': 0}
Duplicate key rule: If a key appears twice in a literal, the later value replaces the earlier one. Only one entry is kept.
04
Accessing Values
ACCESS METHODS 
# Direct access — raises KeyError if key missing
grades = {"Ana": "B", "Matt": "A", "John": "B"}
print(grades["John"])   # → B

# get() — safe access, returns None or default if missing
car = {"model": "i20", "company": "Hyundai"}
print(car.get("color"))              # → None
print(car.get("color", "Not Available"))  # → Not Available

d[key] — Direct

  • Use when key is certainly present
  • Raises KeyError if key is missing
  • Fast and concise

d.get(key, default) — Safe

  • Use when key may or may not exist
  • Returns None if no default given
  • Preferred in defensive code
05
Adding, Updating & Deleting
MUTATION OPERATIONS 
# Add new entry
grades["Grace"] = "A"

# Update existing entry
grades["Grace"] = "C"   # replaces, does NOT move position

# Delete an entry
del grades["Ana"]         # raises KeyError if key absent

# Membership — checks KEYS only
"John" in grades          # → True
"B"    in grades          # → False (values not checked)
Insertion order rule: Updating an existing key's value does NOT change its position. Deleting a key and reinserting it moves it to the end.
06
Traversal — keys(), values(), items()
LOOP STYLES 
grades = {"Ana": "B", "Matt": "A", "John": "B"}

# Default iteration — over keys
for k in grades:
    print(k)              # Ana, Matt, John

# Explicit key iteration
for k in grades.keys():
    print(k)

# Value iteration
for v in grades.values():
    print(v)              # B, A, B

# Key-value pairs (most useful)
for k, v in grades.items():
    print(k, "→", v)    # Ana → B ...

08
Valid Keys and Values

Keys — Stricter Rules

  • Must be unique and hashable
  • ✅ int, float, str, bool, tuple (all-hashable)
  • ❌ list — not hashable
  • ❌ set — not hashable
  • ❌ tuple containing a list — not hashable

Values — Very Flexible

  • Can be any type
  • int, str, bool, float
  • list, tuple, set
  • Another dictionary (nesting)
  • Functions, objects — almost anything
09
Nested Dictionaries
NESTED ACCESS 
grades = {
    "Ana": {"mq": [5, 4, 4], "fin": "B"},
    "Bob": {"mq": [6, 7, 8], "fin": "A"}
}

grades["Ana"]          # → {'mq': [5,4,4], 'fin': 'B'}
grades["Ana"]["mq"]    # → [5, 4, 4]
grades["Ana"]["mq"][0]  # → 5
grades["Bob"]["fin"]   # → A
Rule: Each [key] step goes one level deeper into the structure.
10
Important Methods
d.get(key, default)
Safely retrieve value; returns default (or None) if key is missing — no KeyError.
d.keys()
Returns a view of all keys in insertion order.
d.values()
Returns a view of all values (may contain duplicates).
d.items()
Returns a view of (key, value) tuples — most useful for loops.
d.update(other)
Merges another dict into d. Existing keys are updated; new keys are inserted.
d.pop(key)
Removes key and returns its value. Raises KeyError if key is absent.
d.popitem()
Removes and returns the last inserted (key, value) pair.
d.copy()
Returns a shallow independent copy — use instead of plain assignment to avoid aliasing.
d.clear()
Removes all entries. Dictionary becomes empty {}.
dict.fromkeys(keys, val)
Class method — creates a new dict from an iterable of keys, all with the same value.
COMPREHENSION 
# Dictionary comprehension
squares = {x: x * x for x in range(1, 6)}
# → {1: 1, 2: 4, 3: 9, 4: 16, 5: 25}

evens = {x: x*x for x in range(1, 11) if x % 2 == 0}
# → {2: 4, 4: 16, 6: 36, 8: 64, 10: 100}
11
Assignment vs Copy
ALIASING TRAP 
# ❌ Aliasing — both names point to same dict
d1 = {"a": 1, "b": 2}
d2 = d1
d2["c"] = 3
print(d1)   # → {'a': 1, 'b': 2, 'c': 3}  ← d1 also changed!

# ✅ Shallow copy — independent dictionary
d1 = {"a": 1, "b": 2}
d2 = d1.copy()
d2["c"] = 3
print(d1)   # → {'a': 1, 'b': 2}  ← d1 unchanged
12
Common Mistakes
⚠️ Accessing a dictionary by integer position instead of a key
⚠️ Forgetting that keys must be unique — duplicate keys silently overwrite
⚠️ Using in to check a value — it only checks keys
⚠️ Using a list or set as a key — they are not hashable
⚠️ Assuming mutation methods like update() return a new dictionary (they return None)
⚠️ Using direct indexing (d[key]) when the key might be absent — causes KeyError; use get()
⚠️ Using plain assignment instead of copy() — leads to aliasing bugs
⚠️ Misunderstanding nested access — each [] goes one level deeper
⚠️ Assuming deleting and reinserting a key keeps its original position — it moves to the end
